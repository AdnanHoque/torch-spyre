Three ring-aware bets,
turned into real code.

Residency (pinning to LX) is the trivial floor. The interesting layer is ring-aware algorithms that respect what the fabric actually does: a uniform neighbor shift runs at ~130 GB/s, an all-to-all scatter or linear fold hits a ~36 GB/s floor — because per-link transfer count is the variable, not burst size. Each bet was scouted at its live code site, built in an isolated worktree, verified device-free where the deeptools boundary allowed, and pushed to the AdnanHoque fork as a branch (never a PR).

The device physics these bets play by measured

HBM is one flat space (memId = −1, no channel affinity) — the fabric, not the memory, is where the ordering matters.
Matmul is weight-stationary: M streams past resident weights, M is never a stick.
Cross-bundle wall: LX does not persist across bundles — but a coarse-tile loop is one bundle, so ops inside co-bundle for free.

BET 2

Per-link contention cost term

Done
ah/ring-cost-term · 2dfb2cc
Problem The matmul cost model priced every operand move at flat bytes/128 with one lumped cohort_penalty = max(1, max(m,n)/8) on the whole byte total — so the device-proven multicast (one→many, ~130 GB/s) was priced identically to a scatter (~36 GB/s). Ring-aware wide-cohort plans were unselectable. Fix Decompose the HBM term into its three real streams. LHS [M,K] is identical across the n-cohort, RHS [K,N] identical across the m-cohort — both one→many multicasts, capped at the fast band by _cohort_penalty(cohort, identical=True) = min(max(1,cohort/8), peak/130). The output tile is distinct (no penalty); a distinct-data scatter caps at peak/36. Site work_division.py · _cohort_penalty(), HBM cost term
Verification · device-free
No-regression is structural: _cohort_penalty returns exactly 1.0 for cohort ≤ 8, so banked shared-weight / min-cores cases are byte-identical to before. 7/7 new unit tests measured incl. the exact earlier mispricing — (m2,n16) now costs less than (m8,n4). 153 device-free inductor tests pass measured, ruff clean.

Flash-in-a-loop

Partial
ah/flash-ring · e47f268 + uncommitted _hints_levels follow-up
Problem test_flash.py:17 disallows coarse-tiling in Lk (kv_block_size = Lk//1), so the online-softmax loop runs once and materializes the full [1,32,4096,4096] scores = 32 MB/head — a ~12 ms HBM round-trip measured that defeats the point of flash. Fix (a) an off-stick scores.transpose(-1,-2).contiguous() (mirroring paged) that clears the stick-incompat error and collapses scores to [1,4,1024,4096]; (b) a committed guard _reduction_consumed_only_inside that diverts flash reductions off the fill+combine path and marks per-tile block_max/block_sum as per_tile_fixed lx-resident scratch — so the running (m,l,A) state co-bundles for free. Verification · honest gap
The review caught that the committed guard was inert: _hints_levels read is_reduction from the first (pointwise) op, so Lk never routed through the reduction path. The follow-up fix is described in the callout below — and it still does not fire. Unit safety net: 146 passed / 0 failed measured with the fix applied.
BET 3

LSE ring-fold merge

Design-complete
ah/flash-ring · b36236a · math + schedule validated, not compiler-wired
Problem Once Lk splits across cores (not just time), each core owns a KV shard and emits a partial (m,l,O). A linear fold-to-one root piles full payload on one link → 36 GB/s floor. Fix A neighbor reduce-scatter (1 transfer/link) stays on the ~130 GB/s band modeled and lands the output head-split — exactly the layout the O-projection wants, relayout-free. Frontend composition is buildable now: ring order + per-hop STCDPOpLx cross-core move + a separate SFP lse_combine sub-run; fp32 (m,l,A) combine with dead-lane guard; P−1 combining hops + optional all-gather. Site Frontend composition; deeptools ask filed to deeptools-change-log.md — a single fused move-then-reduce hop, only if per-hop overhead proves too high (not hacked in).
Verification · device-free reference
13/13 reference checks measured incl. fold == single-pass softmax (rtol 1e-4), every round distance-1, head-split endpoint. Bandwidth advantage is modeled from the 130 vs 36 GB/s device physics.

⚠️ The _hints_levels guard — does it fire now?

No. Still inert. Nothing was committed.

The fix is logically correct and was applied as two coupled edits in coarse_tile.py (left uncommitted in the worktree, no commit created):

1. _hints_levels (L95) now OR-reduces is_reduction across every op in the group, so a level is a reduction level when the hinted dim reduces in any op (e.g. block_max/block_sum over Lk), not just the leading pointwise keys*scale.
2. _stamp_group (L1061) now chooses the branch per-op, not from the global level flag — required because once the level flips to reduction, the leading pointwise would get rpos=None and be left un-tiled (iterating full Lk every loop). This is exactly the safety adjustment the task flagged as conditional — it did not hold on its own.

Why it can't be exercised e2e — both vehicles exhausted:

  • Faithful probe (tiles={"Lk"}) aborts at optimize_restickify_locations (pass idx 2) on buf12: "no mechanism to gather elements from multiple sticks into single stick" (the sparse amax(dim=-1) real_max/denominator chain). _maybe_coarse_tile is pass idx 10 — coarse_tile never runs. Identical on base b36236a, guard e47f268, and the fix → pre-existing, cross-commit.
  • Reachable e2e test (test_hint_flash_attention, tiles Lk by 2) compiles fully and reaches coarse_tile — but every stamp is H-only (loop_tiled_dims=[[1]], 0 fill/combine ops). The group's representative op has Lk range=0 / loop_var=None, so Lk never becomes a level. _hints_levels only reclassifies existing levels, so the OR-reduce is moot. Decisive ablation: base vs fix stamps are byte-identical.

Per the task's own rule ("if it still does not fire, commit nothing") the edit sits uncommitted for inspection. Two upstream blockers — both independent of this change — gate firing: (1) optimize_restickify must handle the sparse multi-stick→single-stick gather; (2) assign_dim_hints must surface an Lk level whose representative op iterates Lk while a peer reduces it. Note the harvestenv restickify abort is far upstream of the known deeptools/VFIO end-of-pipeline abort — likely the author's confirming run used a different LD/senlib env where restickify succeeded.
