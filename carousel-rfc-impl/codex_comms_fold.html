Where both efforts stall

Shared blockers

shared DCG coordinate-metadata → physical placement for a KERNEL operand

Both efforts have a passing-but-unreproducible run gated on coordinate-map → physical placement for a replicated/gathered DsTypes::KERNEL operand. Adjacent stages of one pipeline.

Codex side — metadata absent upstream

fillDataInfo throws std::out_of_range map::at on the generated _lx_local transfer transfer_lds1_src:lxlu_dst:ptrow0 because coordDims=0 / coordCoreMap=0 — the coordinate maps are empty. M=4 loop-scoped run value-wrong (949/1024).

Our side — maps present, mispacked downstream

On the fixed latest dxp (a1ec02a), maps are present and assert_multicast_partition passes, but the DCG packer places the 8 replicated dest bands physically wrong. runDcgForInputFetchNeighbor is present-but-dead in-pipeline and hard-pinned to DsTypes::INPUT while the operand is KERNEL.

Implication. Not the literal same exception, but the same deeptools region and the same missing capability. Wiring the DsTypes::KERNEL loop-scoped operand-fetch coordinate path — generalize runDcgForInputFetchNeighbor off INPUT-only + populate/consume the coordinate maps — is the single deeptools task most likely to unblock BOTH passing-but-unreproducible runs. A Deeptools tooling task, not a Torch-frontend gap for either side.

Count-based grouping loses the true coordinate stride.

Codex side

Flash's first-failing edge is value-wrong because the count-based plan groups cores contiguously (0,1,…,7) while the real SDSC coordinate map is strided (0,4,…,28). Count/group metadata alone is too weak.

Our side

Bet 2's edge descriptor must price the true per-link topology. If it emits a cohort count rather than the coordinate stride, the selected plan is mispriced the same way — the same stride-vs-count mismatch as our sendnn-head-grouped vs tsp-Lk-band lineage.

Implication. Bet 2 must carry the true coordinate stride, not a cohort count, and the two-stage plan must key grouping off the actual coordinate maps. Converge the descriptor format with codex's backend-plan JSON (consumer_operand_ds_type: KERNEL, group_count, consumer_replicas_per_group) so the priced edge and the lowered plan agree.
