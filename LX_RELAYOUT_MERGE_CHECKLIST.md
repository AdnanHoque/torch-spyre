# LX relayout materialization — merge checklist

Review of `ah/lx-relayout-from-current-main-b4ae` (`67df28b`), the candidate chosen to
carry the LX relayout materialization feature forward.

## Why this branch

Three implementations of the same feature existed:

| | head | base | size |
| --- | --- | --- | --- |
| A — PR 3439 | `27a1323` | `747c5ef` | +1853/-161, 18 files |
| B — `ah/lx-relayout-lean` | `ad365c72` | `747c5ef` | A plus one refactor commit |
| C — this branch | `67df28b` | `b4ae70f` | +1197/-169, 13 files |

C was chosen because it is the only one on current main — its base carries #3569 (the
`uses`/lifetime model), #3620 (stateful `MemoryPlanSolver`), #3615 (copies survive DCE)
and #3577, all in areas this feature touches. It is also the only one free of A's
`operation_name = "lx_relayout_copy"` defect, where the tag overwrites the id
`register_operation` assigned and then collides as a dict key in `wsr/coarse_tile.py`
and `deadcode_elimination.py` when a graph holds two relayout copies. C identifies
copies structurally instead (`op_spec.py:196-208`) and keys plan identity on an
edge-keyed registry. It is the only candidate whose device test checks numerics at
exact tolerance, and the only one that pins the feature flag.

C's cost is that it inherited B's lifetime model (`buffer.uses = [2*use + 1 ...]`)
without A's producer-input liveness guard. Item 1 below is that guard.

## How to read this

Items are ordered so they can be worked in a single pass. Each carries its file:line,
the change, and a **Verify:** line stating the observable that proves it worked.

One property to keep in mind throughout: this machinery's characteristic failure is not
a crash. An edge that is planned and then silently dropped still produces the correct
token, just slower; an edge with a wrong ownership map, or a buffer aliased against a
live one, produces wrong numbers with no error and no log. Severity here is judged on
that basis — a silent-wrong-numbers path outranks a crash.

Note also that the feature defaults **on**: `config.py:37` is
`_get_env_bool("SPYRE_LX_PLANNER_RELAYOUT", True)`, so the environment variable is an
opt-out. The "opt-in" framing in the PR description does not hold for any of the three
branches.
